# Project output boundary

## Principle

agentic-art-research is a protocol repository. Its tracked content defines the schemas, lifecycle, safety boundary, validators, evaluation gates, and reproducible fixtures. It does not store demos or actual art-research packages.

## Output location

Actual project packages are accumulated outside the protocol repository:

    /Users/masa/マイドライブ/AI-Agent-Pipeline/Agentic-Art-Output/<project-id>/

Each project gets one directory. The directory contains the package generated by the protocol, including its manifest, evidence ledger, decisions, production requirements, governance records, and runtime state.

## Safe execution flow

1. Clone the protocol repository into a temporary work root.
2. Materialize or create one project in that work root.
3. Run validate, graph, bundle, audit, and the relevant completion checks.
4. Copy only the validated projects/<project-id>/ directory to Agentic-Art-Output/<project-id>/.
5. Keep the protocol repository clean: no actual project package under projects/ and no project-derived graph under data/.

The canonical checkout enforces this rule with `PROTOCOL-OUTPUT-BOUNDARY`. Its
`projects/` directory permits only this README, and its `data/` directory
permits only this README and an empty `dependency-graph.json`. The materializing
CLIs require an explicit `--root` so a protocol checkout is not selected by
accident.

The external output package must still obey the repository boundary: no PRIVATE_RAW, RESTRICTED, credentials, or unreviewed source material.
