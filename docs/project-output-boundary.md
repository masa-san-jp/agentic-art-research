# Project output boundary

## Principle

agentic-art-research is a protocol repository. Its tracked content defines the schemas, lifecycle, safety boundary, validators, evaluation gates, and reproducible fixtures. It does not store demos or actual art-research packages.

## Output location

AAK-08 adds a separate owner knowledge boundary under the pinned AAK-SPEC/PLAN
`b0e7c7f8d0a1f756fa708deef4fb380a62e45e0d`. Explicitly curated, owner-schema-validated
records may be committed to an owner knowledge Git store. This does not permit
copying project directories or runtime/raw/profile material into the protocol.
The external store uses `knowledge/records`, `knowledge/payloads`, and
`knowledge/operations`; its graph index is an external regenerable cache.
See [research-memory.md](research-memory.md) for the native interface and resume rules.

Actual project packages are accumulated outside the protocol repository. Set this
location as an environment-specific `OUTPUT_ROOT`; do not hard-code a personal
machine path in automation:

    <output-root>/<project-id>/

Each project gets one directory. The directory contains the package generated by the protocol, including its manifest, evidence ledger, decisions, production requirements, governance records, and runtime state.

## Safe execution flow

1. Keep the protocol repository read-only and select separate work and output roots.
2. Run `tools/harness.py bootstrap` or `tools/harness.py run --request` to atomically materialize protocol assets, one project, and `07_runtime/task_runtime` into the work root.
3. Run validate, graph, bundle, audit, and the relevant completion checks against the explicit protocol/work roots.
4. Publish only the validated package through `harness.py run` or `tools/export_handoff.py` to `<output-root>/<project-id>/`.
5. Keep the protocol repository clean: no actual project package under projects/ and no project-derived graph under data/.

The bootstrap run manifest is stored at `work/.harness/run.json` and is validated by
`schemas/harness-run.schema.json`. It records the protocol commit and dependency
preflight, but bootstrap never writes a project artifact to output. Re-running the
same request hash and run ID returns the existing manifest byte-for-byte; changed
input, non-empty roots, symlinks, nested roots, and broad roots fail closed.

The canonical checkout enforces this rule with `PROTOCOL-OUTPUT-BOUNDARY`. Its
`projects/` directory permits only this README, and its `data/` directory
permits only this README and an empty `dependency-graph.json`. The materializing
CLIs require an explicit `--root` so a protocol checkout is not selected by
accident.

The external output package must still obey the repository boundary: no PRIVATE_RAW, RESTRICTED, credentials, or unreviewed source material.
