# 1件のリサーチを完了する手順

対象は原則として1つの必須調査質問。順序を変えない。

## 1. 受付を確認する

`00_intake/creative-intent.md` と `constraints.yaml` を読み、目的、利用先、期限、公開範囲、禁止事項を確認する。不足していても、制作判断を変えない軽微な項目は保守的な既定値で埋める。

## 2. 重複を確認する

- 同一プロジェクトのquestion、evidence、claimを検索する。
- `profiles/` の関連シグナルを検索する。
- `art-history-notes` のbundleを利用できる場合は検索する。
- 同一URL、同一hash、転載関係の資料を独立証拠として重複計上しない。

## 3. 質問を固定する

質問は、判断対象、必須/任意、必要証拠、最大探索戦略、最大資料数、再開条件を持つ。1タスク中に別の大質問へ拡張しない。

## 4. 証拠を集める

優先順位:

1. 作者、所蔵館、法令、規格、公式記録等の一次資料
2. 査読研究、専門書、展覧会カタログ等の独立した二次資料
3. 制作者の許可済み過去作品、メモ、制作ログから作る最小限の派生シグナル
4. 試作、シミュレーション、遠隔観察

実地観察でないものを実地観察と書かない。権利不明素材は保存・採用しない。

## 5. 証拠台帳へ登録する

ID、source location、取得日時、SHA-256、権利、機密区分、関連質問、直接観察かを記録する。`PRIVATE_RAW` はURIとhashだけを記録し、原文を保存しない。

## 6. 主張を作る

`FACT`、`SOURCE_CLAIM`、`OBSERVATION`、`INTERPRETATION`、`INFERENCE`、`PREFERENCE_SIGNAL`、`HYPOTHESIS` を区別する。重要な主張では反証を探索する。

## 7. 終了を判定する

- 必要な回答と反証が揃った: `ANSWERED`
- 探索上限に達したが不足: `UNRESOLVED`
- 権限または外部依存で進めない: `BLOCKED`

未解決を推測で埋めない。質問を終端にして全体工程へ返す。

## 8. 制作へ変換する

主張からインサイト、判断候補、制作要件、受入試験を作る。必須要件は必ず観察可能な合格条件を持つ。

## 9. 検証する

```bash
python3 tools/validate.py --check
python3 tools/build_graph.py
python3 tools/audit.py
```

## 10. 引き継ぐ

task状態、使用したソース、未解決、再開条件、影響する判断を記録する。次のエージェントが会話なしで再開できることを確認する。
